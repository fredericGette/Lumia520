## Qcq6ad8930.sys

Qualcomm QDSP6 audio driver (Q6AD).  
It is the APR (Asynchronous Packet Router) client of the Windows side: it talks to the audio services of the ADSP (QDSP6) — AFE (ports), ADM (device/COPP sessions), ASM (stream sessions), the voice services (CVS, CVP, MVM) and the ADSP core — by exchanging APR packets over 2 SMD channels (`apr_audio_svc` and `apr_apps2`) of [qcsmd8930.sys](./qcsmd8930.md). The other audio drivers never build APR packets themselves: they get a table of entry points with [IOCTL 0xADAD2BA1](#ioctl-0xadad2ba1--get-q6-entry-points) and call them directly with `0xADADxxxx` command codes, or send a few of these commands as IOCTLs.  
Clients: [qc8x60aud.sys](./qc8x60aud.md) (audio endpoints, voice), [qcaudhwi8930.sys](./qcaudhwi8930.md) (AFE port start/stop), [qcomavsdecoder.sys](./qcomavsdecoder.md) / [qcomavsencoder.sys](./qcomavsencoder.md) (compressed streams) and [qcadsp8930.sys](./qcadsp8930.md) (audio license, [IOCTL 0xADAD2F41](#ioctl-0xadad2f41--audio-license)).  
It waits for the ADSP ([qcadsp8930.sys](./qcadsp8930.md)), SMD and ACDB ([qcacdb8930.sys](./qcacdb8930.md)) interfaces before enabling its own interface, and reads `BATT_THERM` from the ADC driver every second while some AFE ports are running.  
KMDF driver, source file `q6ad_driver.c`, PDB path `E:\build_e\subtask\E05A4CC0_98\output\audio\fre\qcq6ad8930.pdb`. Pool tags `qq6x` (`0x..367171`, e.g. `qq62`, `qq6d`, `qq6t`).

ACPI device `\_SB.Q6AD` (`_HID` `QCOM0750`), with a `_DEP` on `\_SB.ACDB`, `\_SB.ADSP` and `\_SB.SMD0`. `\_SB.QCRT` (qc8x60aud.sys) and `\_SB.ACHW` have a `_DEP` on `\_SB.Q6AD`.

Device name : `\Device\Q6Audio`  
There's no symbolic link (the clients open the device by name or through its interface).

Registries of the driver:  
`HKEY_LOCAL_MACHINE\SYSTEM\ControlSet001\services\qcQ6AD`  
`HKEY_LOCAL_MACHINE\SYSTEM\ControlSet001\Enum\ACPI\QCOM0750\<instance>`

### Start sequence

`DriverEntry` (0x464008): WPP init, reads `SOSLog`, initialises 3 mutexes, `WdfDriverCreate` with `EvtDriverDeviceAdd` only.

`EvtDriverDeviceAdd` (0x463800):  
1. `WdfDeviceInitAssignName(\Device\Q6Audio)`, `WdfDeviceCreate` (context `Q6AD_DEVICE_CONTEXT`, `EvtCleanupCallback` = `sub_4635A0`), `WdfDeviceSetStaticStopRemove(FALSE)`. There are no PnP/power callbacks (no `EvtDevicePrepareHardware`).
2. Creates a WDF timer (`sub_41F10C`, context `TIMER_CONTEXT`), see [Battery temperature](#battery-temperature).
3. Evaluates the ACPI method `INFO` (`sub_4636A4`), see [ACPI INFO](#acpi-info). Failure → the device isn't created.
4. If `SOSLog` is `TRUE`: allocates the [SOS log buffer](#sos-log-buffer).
5. Creates the default queue (`sub_416DC8`): parallel, **not power managed**, `EvtIoDeviceControl` = `EvtWdfIoQueueIoDeviceControl` (0x416B34), `EvtIoInternalDeviceControl` = `EvtWdfIoQueueIoInternalDeviceControl` (0x4168D8). Then a wait lock and the system thread `sub_46256C`. A failure of this step is returned as `STATUS_DEVICE_ALREADY_ATTACHED` (0xC0000365, sic).

System thread `sub_46256C` (each wait has a 10 s timeout; a timeout ends the thread and the driver stays not ready):  
1. Registers for the ADSP interface `{2D332EF9-…}` and waits for its arrival (event context +0x258). Sleeps 1 s, then opens it (`sub_462370`).
2. Registers for the SMD interface `{F9D15453-…}` and waits for it (event +0x268). Initialises APR (`sub_461034`): opens `apr_audio_svc` and `apr_apps2`, allocates the [shared memory](#shared-memory), creates the session tables and mutexes.
3. Registers for the ACDB interface `{4EE2204F-…}` and waits for it (event +0x278). Opens it and gets `acdb_ioctl` (`sub_462114`), then registers its ACPH handler (`sub_4128E4`), see [ACDB](#acdb).
4. Sets the "ready" flag (`byte_42F26C`, `sub_415988(1)`) and creates/enables the device interface `{5F51A34C-6834-479D-9EA2-EAFA622524BA}` (`sub_415AEC`).

The PnP notification callback (`sub_415D58`) queues a work item (`sub_415F18`). On an arrival it sets the matching event. On a removal of the ADSP, SMD or ACDB interface it disables the Q6 interface; on an ACDB removal it also sets context +0x2A4 so that the ACPH handler isn't unregistered at cleanup.

Until the "ready" flag is set (and again after a cleanup), the IOCTLs complete with `STATUS_DEVICE_NOT_READY` (0xC00000A3) and the entry points return -6.

Cleanup (`sub_4635A0`, also called on ADSP query-remove): clears the "ready" flag, closes the APR services (`sub_461280`: ADM 0xFF00 and ASM 0x10000 memory unmaps ?, frees the shared memory, sends `acdb_ioctl(0x50022408)` to remove the ACPH handler 3), closes the ADSP and ACDB targets and unregisters the 3 PnP notifications.

### ACPI INFO

`sub_4636A4` sends `IOCTL_ACPI_EVAL_METHOD` (0x32C004) to the default I/O target with `ACPI_EVAL_INPUT_BUFFER` `{'BieA', "INFO"}` (8 bytes) and a 4096-byte output buffer. The output must be `'BoeA'` with 3 integer arguments, otherwise `STATUS_ACPI_INVALID_DATA` (0xC014000F) is returned.  
| Argument | Lumia 520 | Stored at | Use |
|----------|-----------|-----------|-----|
| 0 | 0x29000000 | context +0x2A8 | Lowest physical address of the [shared memory](#shared-memory) |
| 1 | 0xD6FFFFFF | context +0x2AC | Size of the window: highest address = arg0 + arg1 (0xFFFFFFFF) |
| 2 | 0x50 | `dword_45F444` | ? Not used |

### Shared memory

All the buffers shared with the ADSP are allocated with `MmAllocateContiguousMemorySpecifyCache` (`MmNonCached`) between INFO arg0 and arg0 + arg1:  
| Size | Allocated by | Use |
|------|--------------|-----|
| 4096 | `sub_402780` | ADM / calibration buffer (region descriptor `word_45F4C0`, mapped with handle 0xFF00) |
| 3 × 147456 (0x24000) | `sub_46296C` | 3 buffers (descriptors at `word_45F300`, 20 bytes each) |
| ? | `sub_40C660`, `sub_413080` | ASM (handle 0x10000) and voice buffers |
| 1 MB | `EvtDriverDeviceAdd` | [SOS log buffer](#sos-log-buffer), only if `SOSLog` |

### SOS log buffer

When `SOSLog` is `TRUE`, `EvtDriverDeviceAdd` allocates 0x100000 bytes of contiguous non-cached memory in the INFO window, writes the ASCII marker `q6ad_sos_log_start` at its start (0x80 bytes reserved) and clears the rest. The pointer (`dword_45F4E8`) isn't used anywhere else in the driver: the buffer is probably meant to be found in a RAM dump by its marker ?

### Data logging

`sub_401068` appends a buffer to `\DosDevices\C:\q6ad_buffer_dump.data` (`ZwCreateFile` with `FILE_APPEND_DATA`, `FILE_OPEN_IF`; only at `PASSIVE_LEVEL`). It's called for each buffer written to an ASM stream (`sub_40BE8C`) when `EnableRxDataLogging` is set, and for each buffer read (`sub_40C460`) when `EnableTxDataLogging` is set. All the streams go to the same file.

### SMD channels

Both channels are on edge 1 (APPS↔QDSP), FIFO 0x2000 bytes.  
| Channel | Opened by | How | Use |
|---------|-----------|-----|-----|
| `apr_audio_svc` | `sub_40B3F8` | `WdfIoTargetOpen(\Device\SMD)` + `WdfIoTargetQueryForInterface` SMD Lite `{07631EE5-21BD-455B-BD1F-F41B43F3A9BC}` (Size 0x38, Version 1), then `smdl_open("apr_audio_svc", 1, 3, 0x2000, sub_40B188, NULL)` (packet mode); waits 10 s for the open event | All the APR traffic of the driver (`sub_41437C` sends a packet and waits for the response) |
| `apr_apps2` | `sub_40A8D8` | `WdfIoTargetOpen(\Device\SMD)` + [internal IOCTL 0x22003](#internal-ioctl-0x22003) (flags 0x11 = wait for the remote open), then reads (`WdfIoTargetFormatRequestForRead`, 4096 bytes, `sub_40A404`) and writes (`WdfIoTargetFormatRequestForWrite`, `sub_40ADA4`) | Raw APR packets of the clients of [IOCTL 0xADAD2BC1](#ioctl-0xadad2bc1--get-raw-apr-entry-points). Opened at start and when that interface is reset |

APR header built by the driver (`sub_402088` for the core service):  
| Bytes | Value | Comment |
|-------|-------|---------|
| 00-01 | 50 02 | `hdr_field`: message type 2 (sequenced command), header 5 words, version 0 |
| 02-03 | ? | Packet size (header + payload) |
| 04 | 02 | Source service |
| 05 | 05 | Source domain (APPS) |
| 06-07 | 00 00 | Source port |
| 08 | 03 | Destination service (3 = ADSP core; AFE, ADM, ASM, voice use their own ids) |
| 09 | 04 | Destination domain (ADSP) |
| 0A-0B | 00 00 | Destination port |
| 0C-0F | ? | Token, incremented for each packet (never 0xFFFFFFFF) |
| 10-13 | ? | Opcode, e.g. 0x11285 |

The ADSP answers with `APRV2_IBASIC_RSP_RESULT` (0x110E8) `{opcode, status}`, checked by every command.

### ACDB

`acdb_ioctl` (from the [query interface of qcacdb8930.sys](./qcacdb8930.md#interface-guid)) is used to read the calibration tables (e.g. ACDB commands 0x11290 / 0x11291 for the AFE devices, `sub_407D18` / `sub_4076FC`).  
At start, `sub_4128E4` registers an ACPH command handler with [`0x50022404`](./qcacdb8930.md#acdb-commands) (input `{03 00, 2 bytes, sub_412814}`, 8 bytes): handler id 3 (real-time calibration of the ADSP through DIAG ?). At cleanup (`sub_4630CC`) it's removed with `0x50022408` (input `{03 00}`, 2 bytes), unless the ACDB interface has already gone.

### Battery temperature

When an AFE port is started ([command 0xADAD2B91](#afe-handle-0)) and the port state at +0x1C is 14, 15 or 200 (speaker ports ?), `sub_41F078` opens the ADC interface `{10542F20-…}` (first time only), sends 3 AFE parameters (0x10003102, 0x10003103, 0x10003108, `sub_407F34`) and starts the timer.  
Every second (`sub_41F10C`, relative due time −10 000 000), the timer:  
1. sends `IOCTL_ADC_GET_CHANNEL` (0x8ADC2000) with `BATT_THERM` (11 bytes) → 8 bytes `{found, channel id}`;
2. sends `IOCTL_ADC_READ` (0x8ADC2004) with the channel id (4 bytes) → 20 bytes;
3. stores the converted value (output `04-07`, °C) at +0xB6 and sends it to the ADSP (`sub_409944`, AFE set parameter; speaker protection ?).

The IOCTLs are built with `IoBuildDeviceIoControlRequest` (`sub_41F278`) and waited for 500 ms at most; on timeout the IRP is cancelled and `STATUS_IO_TIMEOUT` (0xC00000B5) is returned. The timer re-arms itself as long as context +0x04 is set.

> [!NOTE]
> For all the IOCTLs of this driver, a failure (input/output buffer too small, or the command returned ≠ 0) completes the request with status 0x00000080 (`STATUS_ABANDONED`), which is a success code for `NT_SUCCESS`.
