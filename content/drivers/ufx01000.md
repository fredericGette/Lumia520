## Ufx01000.sys

USB function class extension, version 1.0 (`UFX`, Microsoft, KMDF 1.11).  
It is a KMDF class library (`WdfRegisterClassLibrary`, version 1.0) that a USB function controller *client* driver binds to with `WdfVersionBindClass`; the client gets the [19 exported functions](#exported-functions) (`UfxFdoInit`, `UfxDeviceCreate`, `UfxDeviceNotify*`, `UfxEndpointCreate`, …). It is the hardware-independent part of the USB device (function) stack, a newer design of the same role as [usbfnclx.sys](./usbfnclx.md): it reads the USB configuration from the registry (`HKLM\SYSTEM\CurrentControlSet\Control\USBFN`), builds the device/configuration/string/MS OS/BOS descriptors, answers the standard requests on EP0, runs the USB device state machine, enumerates one child PDO `USBFN\<interface>` per interface of the active configuration (function drivers such as [genericusbfnclass.sys](./genericusbfnclass.md), [ufnserialclass.sys](./ufnserialclass.md)), dispatches bus events to them and forwards their transfers to the endpoint queues of the client.  
In addition to usbfnclx.sys it handles charger detection (standard/charging/dedicated/invalid/proprietary ports), tells the charging arbitration driver [cad.sys](./cad.md) how much current can be drawn ([internal IOCTL 0x29C4C0](#internal-ioctl-0x29c4c0--ioctl_internal_cad_power_source_update)), publishes the USB state in two WNF states, and implements the "allow USB data connection" user prompt of the shell ([IOCTL 0x2AC110](#ioctl-0x2ac110--enable-data-connection), sent by [MobileUI](../applications/mobileui.md)).  
The client controller driver of this library is [ufxchipidea.sys](./ufxchipidea.md) (ChipIdea HS controller; [usbfnchipidea.sys](./usbfnchipidea.md) is the same driver for usbfnclx.sys). [ufxsynopsys.sys](./ufxsynopsys.md) is the client for the Synopsys DWC3 USB 3.0 controller (probably unused on the Lumia 520).  
Source paths in the binary: `src\drivers\product\drivers\usbfn\ufx\driver\{cad,descriptor,registry}.c`. PDB: `ufx01000.pdb`. Pool tags `UFXD` (0x44584655), `UFXR` (string descriptors). No symbols: the function names below come from the ETW trace strings of the binary.  
The behaviour is driven by two hierarchical state machines (`Device` and `Bus`, framework `Smf*`, declaration `DriverDecl_UFXSM`), see [State machine events](#state-machine-events).

There's no device name.  
The class library creates a control device without name (SDDL `D:P`, kernel only). The client FDO gets an auto-generated name (`UfxFdoInit`: device type 0x2A, `FILE_AUTOGENERATED_DEVICE_NAME`, not exclusive, SDDL `D:P(A;;GA;;;SY)` = SYSTEM only), and registers the device interfaces [`UFX_DEVICE_INTERFACE` `{1b0444ed-…}`](#interface-guid) and, if the client supports proprietary chargers, [`GUID_DEVINTERFACE_CONFIGURABLE_USBFN_CHARGER` `{7158c35c-…}`](#interface-guid).  

GUID of the ETW provider (`Microsoft-WindowsPhone-Ufx`, `EtwRegister`):  
`{e98ebdbf-3058-4784-8521-47860b1d2b8e}`  

### Registry

Key `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\USBFN` (`WdfRegistryOpenKey`, access 0x20000; same layout as for [usbfnclx.sys](./usbfnclx.md#registry)). The device values are read first from the subkey `Default`, then from the key itself (overrides). Missing values keep their default:  
| Registry value | value | comment |
|----------------|-------|---------|
| IncludeDefaultCfg | 0/1 | DWORD |
| bcdDevice | | DWORD ≤ 0xFFFF |
| bDeviceClass, bDeviceSubclass, bDeviceProtocol | | DWORD ≤ 0xFF (note the spelling `bDeviceSubclass`) |
| idVendor, idProduct | | DWORD ≤ 0xFFFF |
| iSerialNumber | | DWORD ≤ 0xFF. ≠ 0 and SMBIOS UUID available → serial number string = SMBIOS system UUID (`IoWMIOpenBlock(SMBIOS_DATA_GUID)`, table type 1) |
| ManufacturerString, ProductString | | REG_SZ. Returned as string descriptors 1 and 2 (the string indexes are hardcoded 1/2/3, there are no `iManufacturer` / `iProduct` values) |
| CurrentConfiguration | e.g. `Default` | REG_SZ, 1–39 characters, name of the configuration loaded at start. Missing → `Default` |

Subkey `Configurations\<name>` (1–256 configurations, name < 39 characters, a configuration named `Default` must exist):  
| Registry value | value | comment |
|----------------|-------|---------|
| InterfaceList | | REG_MULTI_SZ, 1–256 names of subkeys of `Interfaces` (each must exist) |
| bmAttributes | | DWORD ≤ 0xFF |
| bMaxPower | 50 | DWORD ≤ 0xFF, default 50 |
| MSOSCompatIdDescriptor | | REG_BINARY, MS OS extended compat ID descriptor: length = 16 + 24 × count, version 0x0100, index 4, each function's `bFirstInterfaceNumber` < interface count and reserved byte = 1 |

Subkey `Interfaces\<name>` (1–256 interfaces, name < 39 characters):  
| Registry value | value | comment |
|----------------|-------|---------|
| InterfaceDescriptor | | REG_BINARY, required, ≥ 9 bytes: interface descriptor (alternate settings allowed) followed by its endpoint descriptors (and SuperSpeed companion descriptors). Isochronous endpoints are rejected |
| InterfaceGuid | `{…}` | REG_SZ, optional, exactly 38 characters `{xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx}`. Returned in `USBFN_CLASS_INFORMATION_PACKET` |
| MSOSExtendedPropertyDescriptor | | REG_BINARY, optional, version 0x0100, index 5, lengths of the custom properties checked |

Any validation failure → `STATUS_UNSUCCESSFUL` (0xC0000001) and no descriptors.

Key `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Usbfn\Settings` (`UfxRegistryDeviceReadUserPromptSettings`, read when the device state machine starts):  
| Registry value | value | comment |
|----------------|-------|---------|
| PromptForDataConnection | 0 | DWORD, missing = 0. ≠ 0: when connected to a PC, the data connection waits for the user's consent ([IOCTL 0x2AC110](#ioctl-0x2ac110--enable-data-connection)); also read by [MobileUI](../applications/mobileui.md) |

Key `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\ufx01000\Parameters\Smf` (`SmfReadRegistry`, state machine debug options, missing = 0): `VerifyEventHandlers`, `VerifyEventQueueSize`, `VerifyEventInstances` (DWORD).  

The child PDOs are `USBFN\<interface name>` (DeviceID = HardwareID), InstanceID = interface number `%02d`, device text = interface name (0x409). `WdfPdoInitAllowForwardingRequestToParent`: the requests of the children are forwarded to the queues of the client FDO.

It communicates with the following devices:  
| Device | Driver | Comment |
|--------|--------|---------|
| Client FDO (functions given to `UfxDeviceCreate`) | USB function controller client driver [ufxchipidea.sys](./ufxchipidea.md#ufx-interface) (or [ufxsynopsys.sys](./ufxsynopsys.md#ufx-interface)) | [Client callbacks](#client-callbacks); transfers / commands go to its endpoint queues (`WdfRequestForwardToParentDeviceIoQueue`, `IoBuildDeviceIoControlRequest` + `WdfRequestForwardToIoQueue`) |
| Lower device of the client stack (`WdfDeviceGetIoTarget`, ACPI PDO) | acpi.sys | [internal IOCTL 0x32C004](#internal-ioctl-0x32c004--ioctl_acpi_eval_method) `_DSM` |
| Interface `{ec0a1cc9-4294-43fb-bf37-b850ce95f337}` (`GUID_DEVINTERFACE_CHARGING_ARBITRATION`, `IoRegisterPlugPlayNotification`) | [cad.sys](./cad.md) | [internal IOCTL 0x29C4C0](#internal-ioctl-0x29c4c0--ioctl_internal_cad_power_source_update) |
| WMI `SMBIOS_DATA_GUID` (`IoWMIOpenBlock`, `IoWMIQueryAllData`) | | SMBIOS table, system UUID for the serial number |

### Client callbacks

Offsets in the `UFXDEVICE_CONTEXT` (the client's 68-byte callback structure is copied at +0x28, Size first):  
| Offset | Called from | Use |
|--------|-------------|-----|
| 0x2C | `Connecting` state | Host connect (start the controller) |
| 0x30 | `Disconnecting` state | Host disconnect |
| 0x34 | `SET_ADDRESS` | Addressed |
| 0x38 | `UfxBusCreateChildPipes` | Endpoint add |
| 0x3C | `FF_DeviceDefaultEndpointAdd` | Default endpoint (EP0) add |
| 0x40 | `FF_DeviceStateChange` | USB state change (1 Attached, 2 Default, 3 Detached, 4 Addressed, 5 Configured, 6 Suspended) |
| 0x44 | `FF_DevicePortChange` | Port type change |
| 0x48 | `Detecting` state | Start port (charger) detection, answered with export 9. Optional |
| 0x4C | `FF_DeviceSignalRemoteWakeup` | Signal remote wakeup |
| 0x50 | `Restart` state | Controller reset |
| 0x54 | `TestMode` state | Test mode set (selector from `SET_FEATURE(TEST_MODE)`) |
| 0x58 | [internal IOCTL 0x2AC108](#internal-ioctls-on-the-child-pdos) | Test hook (optional, else `STATUS_INVALID_DEVICE_REQUEST`) |
| 0x5C | `SET/CLEAR_FEATURE(U1/U2_ENABLE)` | SuperSpeed power feature |
| 0x60 / 0x64 / 0x68 | `DetectingPdcp` / [internal IOCTL 0x29C500](#internal-ioctl-0x29c500--proprietary-charger-set-property) / `Detached` | Proprietary charger detect / set property / reset (required when `PdcpSupported`) |

Capabilities (16 bytes at +0x6C): byte 12 = `PdcpSupported` (proprietary dedicated charging port).

### State machine events

Event numbers (`SmfEnqueueEvent`), from the event name table at `.rdata:0x1001A1B4`:  
| Event | Name | Event | Name |
|-------|------|-------|------|
| 26 | BusClassDriverDeactivateRequest | 47 | DevicePortHost |
| 27 | BusClassDriverActivateRequest | 48 | DevicePortInvalidCharger |
| 38 | DeviceUpdateWaitForUserPrompt | 49 | DevicePortCharger |
| 39 | DeviceEnableDataConnection | 50 | DevicePortUnknown |
| 43 | DeviceRemoteWakeupSignal | 54 | DeviceNotifySetup |
| 45 | DeviceChargeTimer | 63–69 | DeviceNotifyHardwareReady / HardwareFailure / Reset / Resume / Suspend / Detach / Attach |
| 46 | DevicePdcpSetProperty | 70 | DeviceEventComplete |

Connection sequence (`Attached` states): `Detecting` calls the client's port detection (0x48); a host port (SDP/CDP) goes to `WaitForUserPrompt` when `PromptForDataConnection` ≠ 0, where the device is "forced host" (port type SDP, 500 mA, or 900 mA at SuperSpeed) and `WNF_OS_USB_DEVICE_STATE` = 2 is published, until [IOCTL 0x2AC110](#ioctl-0x2ac110--enable-data-connection) arrives; then `Connecting` calls the client's host connect (0x2C) and starts a 5 s charge timer (`DeviceChargeTimer`). If the timer expires before the host enumerates the device, the port is treated as an invalid charger ? (500 mA, weak charger).

`WNF_OS_USB_DEVICE_STATE` (0x41C61D22A3BCC075, 4 bytes) published by `WnfPublishUsbDeviceState`:  
| Value | When |
|-------|------|
| 0 | Device created, Detach |
| 1 | `SET_CONFIGURATION` (Configured) |
| 2 | Attached to a host, waiting for the user prompt (`FF_DeviceForceHost`) |
| 3 | CDP / DCP charger |
| 4 | Invalid DCP (also `WNF_OS_USB_CHARGER_WEAK_SHOW` = 1) |
| 6 | Proprietary charger |

`WNF_OS_USB_CHARGER_WEAK_SHOW` (0x41C61D22A3BCB075, 4 bytes): 1 on an invalid dedicated charger, 0 when the port type changes from invalid DCP to another type. Both states are read by [MobileUI](../applications/mobileui.md) (weak charger and USB data dialogs).

Current notified to [cad.sys](./cad.md): SDP 0 mA until configured, then 500 mA (900 mA at SuperSpeed); CDP / DCP / proprietary 1500 mA; invalid DCP 500 mA; Detach 0 mA, not connected. A notification is only sent when it differs from the previous one and is consistent with the logical power state (`ValidatePowerSourceNotification`).

### Descriptors

- Device descriptor from the registry, `bcdUSB` / `bMaxPacketSize0` updated for the speed (`UfxDescriptorUpdateDeviceSpeed`); device qualifier and other-speed configuration only at high speed.
- String descriptors: 0 (language 0x0409 only), 1 `ManufacturerString`, 2 `ProductString`, 3 serial number (SMBIOS UUID), 0xEE MS OS string descriptor `MSFT100` with vendor code 0x42. Vendor requests with `bRequest` 0x42 and `wIndex` 4 / 5 return `MSOSCompatIdDescriptor` / `MSOSExtendedPropertyDescriptor` (one page only).
- BOS descriptor (`GET_DESCRIPTOR` type 15) only at SuperSpeed: 22 bytes, USB 2.0 extension (LPM) + SuperSpeed device capability (speeds 0x000E, U1 exit 10 µs, U2 exit 2047 µs).
- Endpoint limit: `_DSM` (`UfxAcpiInvokeMethodDsm`, GUID `{fe56cfeb-49d5-4378-a8a2-2978dbe54ad2}`, revision 0, function 1, no argument) on the controller's ACPI device returns the number of physical endpoints (integer ≤ 32); default 32. Too many endpoints in a configuration → "Too many endpoints!".

### Bus events

Events queued to the children and returned by [internal IOCTL 0x2AC036](#internal-ioctls-on-the-child-pdos) (12 bytes `{event, data[8]}`, `FF_DeviceCreateBusEvent`): 1 Attach, 2 Reset (+speed: 1 full, 2 high, 3 super), 3 Detach (also on test mode), 4 Suspend, 5 Resume, 6 SetupPacket (+8 bytes, class/vendor requests for the child's interface), 7 Configured (+1), 8 Unconfigured, 10 BusTearDown. Same values as with [usbfnclx.sys](./usbfnclx.md#bus-events).

### Internal IOCTLs on the child PDOs

Function drivers send these to their `USBFN\<interface>` PDO (`Child_EvtIoInternalDeviceControl`, 0x100089E0). Same codes as with [usbfnclx.sys](./usbfnclx.md#internal-ioctls-on-the-child-pdos) (`usbfnioctl.h`). InputBuffer `00-03` = `USBFNPIPEID` where needed; a pipe that doesn't belong to the child → error "PipeID provided doesn't belong to the child".  
Before the child sends ACTIVATE_USB_BUS, only 0x2AC022 and 0x2AC02C are accepted, the others get `STATUS_INVALID_DEVICE_STATE` (0xC0000184).  
| Code | Name | Handling |
|------|------|----------|
| 0x2AC00D, 0x2AC011, 0x2AC016 | TRANSFER_IN, TRANSFER_IN_APPEND_ZERO_PKT, TRANSFER_OUT | Forwarded to the transfer queue of the endpoint in the client FDO. 0x2AC011 is rewritten into 0x2AC00D when the length is non-zero and not a multiple of `wMaxPacketSize`. A transfer on a suspended device with remote wakeup armed raises `DeviceRemoteWakeupSignal` |
| 0x2AC018, 0x2AC01C | CONTROL_STATUS_HANDSHAKE_IN/OUT | Forwarded to the EP0 transfer queue |
| 0x2AC022 | GET_CLASS_INFO | Output 748 bytes `USBFN_CLASS_INFORMATION_PACKET` (full-, high- and super-speed interfaces, see [genericusbfnclass.sys](./genericusbfnclass.md#usbfn_class_information_packet)); output of only 552 bytes accepted for class drivers "not compiled with latest WPDK" (no super-speed part). PipeArr[0] = EP0 |
| 0x2AC026 / 0x2AC029 | GET_PIPE_STATE / SET_PIPE_STATE | Input PipeId; forwarded to the command queue of the endpoint. Output length 0 → `STATUS_INVALID_PARAMETER` |
| 0x2AC02C | ACTIVATE_USB_BUS | Event `BusClassDriverActivateRequest` (27) with the interface number, child marked active |
| 0x2AC030 | DEACTIVATE_USB_BUS | Event `BusClassDriverDeactivateRequest` (26), child marked inactive |
| 0x2AC036 | BUS_EVENT_NOTIFICATION | Parked in the child's notification queue, completed with the next [bus event](#bus-events) |
| 0x2AC108 | Test hook (`IOCTL_INTERNAL_USBFN_RESERVED`) | Passed to client callback 0x58 with the input and output buffers |
| 0x2AC10C | Signal remote wakeup | If one of the child's endpoints is armed for remote wakeup: `DeviceRemoteWakeupSignal` (43) and `STATUS_SUCCESS`; else `STATUS_INVALID_DEVICE_STATE` |

Any other code → `STATUS_INVALID_DEVICE_REQUEST` (0xC0000010).

### Internal IOCTLs sent to the client endpoint queues

Built with `IoBuildDeviceIoControlRequest` (internal) on the client FDO and forwarded to the endpoint's command queue (`UfxSendIoctlToInternalQueue`), or to the EP0 transfer queue for UfxDescriptor answers. Processed by [ufxchipidea.sys](./ufxchipidea.md#internal-ioctls-of-the-command-queue) (and [ufxsynopsys.sys](./ufxsynopsys.md#internal-ioctls-of-the-command-queue)):  
| Code | Name | Use |
|------|------|-----|
| 0x2AC00D / 0x2AC011 / 0x2AC016 | TRANSFER_IN / IN_APPEND_ZERO_PKT / OUT | `UfxControlSend`: data stage of the standard requests answered by UFX |
| 0x2AC018 / 0x2AC01C | CONTROL_STATUS_HANDSHAKE_IN/OUT | `UfxControlHandshake` |
| 0x2AC026 | GET_PIPE_STATE | `GET_STATUS(endpoint)` |
| 0x2AC029 | SET_PIPE_STATE | `SET/CLEAR_FEATURE(ENDPOINT_HALT)`, stall of EP0 for unsupported requests |
| 0x2AC401 | Descriptor update ? | `UfxEndpointDescriptorUpdate`: new endpoint descriptor after a speed change (Function 0x100, `METHOD_IN_DIRECT`) |

### IOCTL 0x2AC110 — Enable data connection

This IOCTL is processed by Ufx01000.sys (`UfxDeviceIoControlInternal`, called by the client's `EvtIoDeviceControl`, interface `{1b0444ed-…}`).  
It is sent by [MobileUI](../applications/mobileui.md#ioctl-0x2ac110--usb-data-connection-allowed-) (`UsbDataAlertDialog::NotifyUsb`).

| Property | Value |
|----------|-------|
| Device | 0x2A |
| Function | 0x44 (68) |
| Access | READ_AND_WRITE |
| Method | METHOD_BUFFERED |

| Name | InputBuffer size | OutputBuffer Size |
|------|------------------|-------------------|
| Enable data connection | ≥ 8 | 0 |

Inputbuffer:  
| Bytes | Value | Comment |
|-------|-------|---------|
| 00-03 | 08 00 00 00 | Size (not checked) |
| 04 | 01 | Must be 1 |
| 05-07 | 00 00 00 | |

Byte 4 = 1 → event `DeviceEnableDataConnection` (39): leaves `WaitForUserPrompt`, `DataConnectionEnabled` = 1, client host connect. Any other value → `STATUS_NOT_SUPPORTED` (0xC00000BB), nothing changes (the phone stays charge-only). Input < 8 → error of `WdfRequestRetrieveInputBuffer`.
