## VideoSink_RT.dll

The Windows Runtime version of the Media Foundation video sink: the runtime class `Windows.Phone.Media.Capture.MediaCapturePreviewSink`, a media sink that hands the video frames over ALPC to the processes that display them.  
`VideoSink_RT.dll` (386 functions, no symbols except the PDB name `videosink_rt.pdb`; error strings are the assertion texts of the source) is built from the same source as [VideoSink.dll](./videosink.md): same stream sink, same Direct3D 11 sample allocator, same [ALPC broadcast server](#alpc-broadcast-server) and message protocol, same AV sync markers. The differences: it is a WRL in-process server activated by class name (`DllGetActivationFactory`), the object is also an `IMediaExtension` / `IClosable` that a WinRT app can give to the media capture API, the ALPC port name is generated by the sink (or given to its factory) and readable back as an `HSTRING`, the port gets no SecRuntime security descriptor, and there is no output trust authority ([VideoSinkOTA.dll](./videosinkota.md)), no PDC scenario, no `IMFRateSupport`, `IQualProp` or video render service.  
The class name says that it is the preview sink of the Windows Phone 8 camera API (`Windows.Phone.Media.Capture`, not analysed): the preview frames of the camera are sent to the ALPC clients of the sink; no documented binary loads it or connects to its port. Related binaries: [VideoSink.dll](./videosink.md) (the media engine version) and [VideoSinkOTA.dll](./videosinkota.md), extracted with it.

Location on the phone: ? (extracted next to `VideoSink.dll` and [VideoSinkOTA.dll](./videosinkota.md)).

### Activation

The factory (`sub_10005568`, 44 bytes) implements `IActivationFactory`, a factory interface `{0D3695A8-BC5D-4D38-A1DE-04A753D37BED}`, `IClosable` (`Close` does nothing) and `IAgileObject`.

- `IActivationFactory::ActivateInstance` (`sub_10004F84`): creates the sink object (`sub_10007CDC`), then `GeneratePortName` (`sub_10004BF0`, disassembly only), and returns its `IInspectable`.
- Factory method 6 (`sub_10004F20`), `Create(HSTRING portName, out sink)`: creates the sink object and calls `SetPortName` (`sub_10004D00`, disassembly only); returns the `IMediaExtension` interface (+0x14).

`GeneratePortName` (`sub_10004BF0`):
1. Creates the stream sink (`sub_10007E88`).
2. `CoCreateGuid`, `StringFromCLSID` → `{GUID}`.
3. `RtlGetAppContainerNamedObjectPath(NULL, NULL, FALSE, &path)` (error returned as NTSTATUS | 0x10000000). Outside an app container (`path.Buffer` NULL) the name is `\BaseNamedObjects\{GUID}`, otherwise `<path>\{GUID}` (the `\Sessions\<n>\AppContainerNamedObjects\<SID>` directory of the caller), at most 260 characters.
4. Calls method 4 of the private interface `{BCCD7224-…}` (`SetBroadcastPort`, [Sink object](#sink-object)) with security name NULL and that name.

`SetPortName` (`sub_10004D00`): the `HSTRING` must not contain a NUL and must not be empty (`E_INVALIDARG`, `RoOriginateErrorW(…, L"Argument required to be in BNO form")`); creates the stream sink, copies the name (260 characters at most, else `HRESULT_FROM_WIN32(ERROR_INSUFFICIENT_BUFFER)`) and calls `SetBroadcastPort(NULL, name)`. The name is used as given, so it must be a full object path (`\BaseNamedObjects\…` or the app container's directory).

### ALPC broadcast server

Same code as in [VideoSink.dll](./videosink.md#alpc-broadcast-server): `SetBroadcastPort` (`sub_1000B668`) creates a 0x1C-byte broadcaster (`sub_1000D460`: two events, the server port object and a listening thread started by `sub_1000D6A4`).

Port creation (`sub_1000E610`):
1. Only if a security name is given: `QueryTransientObjectSecurityDescriptor(8 = AlpcPort, name, &sd)` ([SecRuntime](./secruntime.md)). The DLL always passes NULL ([Activation](#activation)), so the port gets the default security of the caller's token (in an app container, that of its named object directory).
2. `NtAlpcCreatePort(&port, {Length 0x18, ObjectName = port name, SecurityDescriptor = sd or NULL}, attributes)`: flags 0x60000, QoS length 12 `SecurityImpersonation` / dynamic tracking / effective only, `MaxMessageLength` 0x60.
3. A 0x60-byte message buffer and a message attribute buffer for `ALPC_MESSAGE_CONTEXT_ATTRIBUTE` (0x20000000).

Messages (`DispatchMessage`, `sub_1000D288`; `PORT_MESSAGE` header then a DWORD type at +0x18, exact size checks): the same types and layouts as in VideoSink.dll — 0 client gone (internal, ETW 141), 1 client connected (internal: message 2 if the sink runs, ETW 140), 2 stream start / reset (→ clients, +0x20 generation, +0x24 "OTA enabled" byte, always 0 here), 4 sample (→ client, 0x60 bytes, [layout](./videosink.md#sample-message): shared handle, sync event GUID, `GetTickCount` deadline, presentation time, video size, generation, subresource index, pixel aspect ratio; built by `sub_1000DB00`), 5 ignored, 6 sample returned (← client, 0x30 bytes, `sub_1000D880`), 7 frames dropped (← client, added to stream +0x270, ETW 142), 10 token (← client, `sub_1000D91C`: `NtAlpcImpersonateClientOfPort`, `OpenThreadToken`, `RevertToSelf`). The GPU sync event of a client is made by `sub_1000EBE0` (`CoCreateGuid`, `StringFromGUID2`, `BuildSecurityDescriptorForSharingAccess(clientToken, 0, SYNCHRONIZE)`, `CreateEventW(sd, FALSE, FALSE, L"{GUID}")`).
